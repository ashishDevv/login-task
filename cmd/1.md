🧠 First: Two meanings of “context”

1. Go context.Context (the real one)

This is the standard thing:

ctx context.Context

Used for:

request lifecycle

cancellation

passing request-scoped data

2. “Logger with context” (just a phrase)

This does NOT mean Go context automatically

It just means:

> A logger that already has some fields attached



Example:

No context.Context involved here.

Problems:

❌ Breaks in non-HTTP code (cron jobs, CLI, tests)

❌ Hidden dependency (not explicit)

❌ Harder to understand function requirements


👉 Companies generally do NOT rely only on context for logger

🧠 Why that works

Remember this:

baseLogger := zerolog.New(...).With().
    Str("app", "my-app").
    Logger()

Now when you do:

reqLogger := baseLogger.With().
    Str("request_id", "abc123").
    Logger()

👉 reqLogger inherits everything from baseLogger

So it contains:

{
  "app": "my-app",
  "request_id": "abc123"
}


---

🔥 Key concept: Zerolog is immutable-style

Every .With():

does NOT modify the original logger

returns a new logger with extra fields


So:

baseLogger  → { app=my-app }

reqLogger   → { app=my-app, request_id=abc123 }


---

✅ When you attach it to context

ctx := reqLogger.WithContext(r.Context())

Then later:

logger := zerolog.Ctx(ctx)

👉 This logger already includes:

app

request_id

anything else you added earlier



---

⚠️ When it would NOT have app

Only if you did this (wrong way):

reqLogger := zerolog.New(os.Stdout).With().
    Str("request_id", "abc123").
    Logger()

👉 Now you lost app, because you didn’t derive from base logger.

Step 1: base logger (in main)

logger := zerolog.New(os.Stdout).With().
    Timestamp().
    Str("app", "my-app").

reqLogger := h.logger.With().
    Str("request_id", reqID).
    Logger()

ctx := reqLogger.WithContext(r.Context())

logger := zerolog.Ctx(ctx)

🧠 Mental model (final clarity)

base logger

  → app=my-app
  → request_id=abc123
  → + dynamic fields

> Always derive new loggers from the existing one
❌ Never create fresh loggers in the middle of the app

Step 3: Combine logger + trace in middleware

Now enhance your existing logging middleware:

func LoggingMiddleware(baseLogger zerolog.Logger) func(http.Handler) http.Handler {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {

            ctx := r.Context()

            // get trace info from OTEL
            span := trace.SpanFromContext(ctx)
            traceID := span.SpanContext().TraceID().String()

            reqLogger := baseLogger.With().
                Str("trace_id", traceID).
                Str("path", r.URL.Path).
                Logger()

            ctx = reqLogger.WithContext(ctx)

            next.ServeHTTP(w, r.WithContext(ctx))
        })
    }
}
